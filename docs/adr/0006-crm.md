# CRM: leads, contacts, organizations, deals

Status: accepted, 2026-10-21 (Phase 3)

HubSpot is no longer used. The website's contact form writes to our own database, and the CRM in the dashboard is the system of record.

## Flow

```
website form -> Lead -> (qualify | disqualify) -> convert -> Contact + Organization + Deal
                                                             Deal: New -> Discovery -> Proposal -> Negotiation -> Won | Lost
```

- **Intake** (`features/crm/intake.ts`, called by `app/api/contact`): Turnstile, honeypot-style limits and the body-size cap are unchanged. One transaction creates the `Lead` (full submission kept in `answers`; the fields used in lists are promoted to columns), links it to an existing contact with the same email, writes the first timeline entry and a "Reply to ..." task due the next day, and appends an audit row. If the database is down the visitor sees the same "email us directly" message as before.
- **Convert** (`features/crm/actions/leads.ts`) is one transaction: reuse or create the contact (live emails are unique, case-insensitively, enforced by a partial unique index), reuse or create the organization when a business was named, create the deal in _Discovery_ (qualified lead) or _New_, and mark the lead converted. Nothing is duplicated if the same person writes in again.
- **Deals** move between open stages with a select (keyboard and phone friendly); _Won_ and _Lost_ have their own steps with their own requirements.

## Rules (pure, tested, shared by UI and server: `features/crm/rules.ts`)

| Area                     | Rule                                                                                                                                                                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Leads                    | New -> qualified -> converted; disqualifying needs a reason and completes the lead's open tasks; only a disqualified lead can be reopened; a converted lead can't be disqualified or deleted.                        |
| Deals                    | Closed deals must be reopened before moving. Winning needs a final value (> 0); losing needs a reason and completes open tasks. A won deal's value is locked. A won deal can't be deleted. No tasks on closed deals. |
| Contacts / organizations | A contact with live deals can't be deleted; an organization with deals or contacts can't be deleted.                                                                                                                 |
| Money                    | Integer centavos + ISO currency (`lib/money.ts`); the form accepts "12,500.50", never floats. Database checks: non-negative, won needs an amount, lost needs a reason, not both won and lost.                        |
| Deletion                 | Leads, contacts, organizations and deals are soft-deleted (`deleted_at`) and hidden everywhere; tasks and timeline entries are not.                                                                                  |

## Data

`organizations`, `contacts`, `leads`, `pipeline_stages`, `deals`, `activities`, `tasks`. Stages are **rows**, not an enum, so names, order and win probabilities can change without a migration; the weighted forecast is `sum(deal value x stage probability)`. Leads and deals get readable references (`LD-2026-0001`, `DL-2026-0001`) from sequences. Every mutation writes an `audit_log` row in the same transaction.

## Permissions and roles

`leads`, `contacts`, `organizations`, `deals`, `tasks` resources (view/create/update/delete, plus `leads:convert` and `deals:close`). A built-in **Sales** role gets everything except deletes and administration; Viewer is read-only; Admin and Owner have all of it.

## Not built yet (tracked in the roadmap)

- Email to staff when a lead arrives, and sending email to contacts (Resend, Phase 8). Until then the dashboard is the notification.
- Tags, CSV import/export, duplicate-merge, saved views, and editing pipeline stages in the UI.
- Drag-and-drop on the board (a stage select is used instead, on purpose, for accessibility).
- Rate limiting is per server instance (in memory). Move it to the database or Redis before running more than one instance.

## Privacy

The privacy policy no longer names HubSpot; it names "our database provider". Have the policy reviewed before launch: it now describes the data we keep in our own system, and a retention period for leads should be stated.
